Additional observations addressed:

- S-01/S-05: successful event subscribers are remembered across an in-process retry; duplicate subscriptions are ignored; the delivery cache is bounded. Aggregate event arrays are copies, the interface uses `clearDomainEvents`, and the bus is exported. Persistence still precedes delivery: this is not a durable outbox or an exactly-once guarantee across crashes/concurrent delivery/cache eviction. Transactional delivery design remains open for repository/module review.
- S-02: removed the unused conflicting shared mail adapter and made the user-management port a compatibility export of the shared email contract. The active adapter builds reset/verification links from the primary frontend origin. SMTP behavior and delivery workflows need their user-management review.
- S-03: shared validation uses `details: Record<string, string[]>`; shared helpers, types and storefront extraction agree. Field details survive the shared Fastify response schema. Module-specific response schemas and the generated SDK contract still need full route-level checks.
- S-04: UUID spelling is normalized and equality requires matching semantic ID type.
- S-06: shared pagination input has one schema with a maximum page size of 100. Domain and transport pagination interfaces remain separate intentionally; module-specific pagination contracts need their module reviews.
- S-07: rate-limit cleanup is lazy and has no background timer; test mode exercises actual limiting. Stores remain process-local and need shared storage if deployment requires aggregate limits across multiple API processes.
- S-08: retry clones use weak request keys, refresh calls share one in-flight promise, refresh failures return the unauthorized response, and openapi-fetch is a runtime dependency. Concurrent refresh and network-failure regression tests pass.
- S-09: removed unused Prisma 5 dependency from core. Root backend compiler remains strict; frontend/client packages retain their framework-specific presets. Shared formatting is now actively checked. This does not establish that every dormant configuration preset is consumed.
- S-10: each API instance owns a Prisma client; `/ready` queries DB separately from `/health`; startup/listen failures are caught and signal handlers close the server. The existing singleton composition container still needs full isolation/lifecycle review.
- S-11: CORS uses normalized validated origins. Swagger CSP/access policy remains a deployment decision, not a confirmed vulnerability fixed here.
- S-12: removed the unused unreachable `Currency.isCrypto()` method. Supported currency policy is unchanged.

- Backend TypeScript, storefront TypeScript, admin TypeScript and API-client TypeScript passed during remediation. Backend lint and storefront/admin lint passed; existing unused-variable and image warnings remain.

Measured coverage snapshot (326-test run, broad backend scope including unregistered modules): **11.66% lines, 7.77% branches, 11.36% statements, 15.38% functions**. This is overall unit coverage, not changed-line coverage. Reports are generated under ignored `coverage/` and uploaded by CI. University targets U12 (80% new-code lines/branches) and U13 (90% critical business branches) are **not demonstrated**. No thresholds were lowered or files excluded simply to claim compliance. Critical-code mapping, missing behavior tests and meaningful coverage enforcement remain open work.

Operational effects:

- Existing access tokens without a session ID must be refreshed or replaced by signing in again. All production protected requests now require a valid persisted session.
- Configure all three FedEx credentials to enable that carrier. Previously embedded values, if real, need revocation/rotation by the credential owner; deleting defaults does not remove repository history.
- Local unit command: `pnpm test`; coverage: `pnpm run test:coverage`; checks: `pnpm run type-check`, `pnpm run lint`, `pnpm run format:check`.
- Database suites: provision a disposable PostgreSQL database with a name such as `ecommerce_test`, explicitly set `TEST_DATABASE_URL` and `ALLOW_DATABASE_TEST_CLEANUP=1`, then run `pnpm run test:vitest`. Never point this at a database holding useful data.
